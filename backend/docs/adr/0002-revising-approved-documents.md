# 已批准文档以「新修订版」方式再编辑

已批准（APPROVED）文档需要能被再次编辑。为满足 21 CFR Part 11「已签署记录不可销毁」的约束，我们不采用破坏式重置，而是采用**新修订版模型**：对已批准文档发起变更时，先把当前已批准内容+版本+其电子签名冻结为不可变历史快照（`DocumentVersion`），然后活动文档退回 `DRAFT` 并次版本进位，需重新提交并重新审批签名才能再次 APPROVED。

## Status

accepted

## Considered Options

- **A. 破坏式重置**：再编辑即清除/失效原有 APPROVED 状态、工作流与电子签名。被否——会销毁已签署的批准记录，违反 Part 11 审计与签名不可否认要求。
- **B. 新修订版模型**（采用）：历史批准版本与签名冻结保留，活动文档开启新的草稿→审批周期。

## Consequences

- 新增显式动作 `POST /documents/{id}/revise`（强制变更原因）：单事务内冻结快照 → `APPROVED`→`DRAFT` → 次版本进位。
- 版本号规则：`0.1` 起；批准通过时主版进位（首批 `1.0`）；发起变更回草稿次版进位（`1.1`）；再批准 `2.0`。
- 旧电子签名保持 `is_valid=True`，绑定被冻结的历史版本，永久保留；`is_valid` 仅保留给哈希校验失败等真·失效场景。发起变更时，对被取代版本的每条签名各写一条 `SIGNATURE_VOID` 审计（记录其对当前文档不再生效、被变更取代，但不改 `is_valid`、不销毁记录）。
- 旧工作流实例原样保留为历史；重新提交时新建工作流。
- 暂不启用 `DocumentStatus.SUPERSEDED`；历史版本由 `document_versions` 快照表体现。
- 下游可追溯性（如引用该文档的 FS/DS）联动失效不在本次范围内。
